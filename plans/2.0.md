# AgentSkills CLI 2.0 plan

Status: planned. Last updated 2026-11-05.

## Goal

Make AgentSkills CLI the most useful skills tool for .NET teams and beyond: a superset of NuGet's
[`dotnet-package-skills`](https://github.com/NuGet/Client.Tools/tree/main/dotnet-package-skills)
(everything it does for NuGet, at least as safely), plus what only we offer: npm, git sources,
several agents at once, updates, restore, private feeds, and CI support.

## Release strategy

- **1.1.0** ships first (PR #1). It contains the update/outdated/restore work, name-conflict aliases,
  version reporting, private feeds and registries, package source mapping, and the NuGet `skills/`
  package layout. It is the base for 2.0.
- **2.0.0** contains everything below. It's a major version because of the breaking changes listed
  further down.
- **.NET 8 stays supported** in 2.0 (`net8.0` and `net10.0` builds; .NET 11+ through roll-forward).
- **Previews** (`2.0.0-preview.N`) may be published as blocks land, so users get `sync` early.
  Decision pending.
- Development happens on `main` once 1.1.0 is released. Fixes for 1.1.x go on a `release/1.1` branch
  if needed.

## Already done in 1.1 (not repeated here)

- NuGet `skills/<name>/` at the package root as the recommended layout (shared with
  `dotnet-package-skills`), `contentFiles` still read.
- `feed` and `registry` commands; skills-only `.agents/nuget.config` and `.agents/.npmrc`.
- Package source mapping, credential providers, project `NuGet.config`.
- `update`/`outdated` for every source type, `--version-lock`, `restore --frozen`, `--json`, `--exit-code`.
- Name conflicts with `--as` aliases and `--replace`.
- Lock file safety: corrupt-file backups, newer-format protection, atomic writes, unknown fields kept.

## Scope

Sizes: S is about a day, M a few days, L a week or more.

### Block A: beat `dotnet-package-skills` on its home turf

| # | Item | Size | Done when |
|---|---|---|---|
| A1 | **`sync`: skills from the project's own dependencies** | L | Reads the project's resolved NuGet packages from `obj/project.assets.json` (fallback: `dotnet list package --format json`) and copies their skills from the local NuGet packages folder: no download, works offline. Also reads npm `package.json` dependencies (from `node_modules` or the registry). Installs for every agent, symlink or copy. Re-running after a package upgrade moves skills to the new version and drops skills the new version no longer ships. Handles solution/project discovery, `NUGET_PACKAGES`, fallback folders. Direct dependencies by default; `--transitive` opts in. |
| A2 | **Stale skills** | M | `sync` reports skills whose package left the project; `sync --prune` and `remove --stale` remove them. Never automatic. |
| A3 | **`--dry-run` everywhere** | M | `add`, `remove`, `update`, `restore`, `sync` print the same report and write nothing. |
| A4 | **Coexistence with `dotnet-package-skills`** | S | Read `.agents/skills/.dotnet-package-skills.json`: `list` shows its skills with package and version; conflict messages say "managed by dotnet-package-skills"; optional `import` moves them into our lock. |
| A5 | **Folder name as the install name for package skills** | S | For NuGet/npm package skills, install under the folder name (what `dotnet-package-skills` does) and warn when it differs from `SKILL.md`'s `name`. *Breaking.* |
| A6 | **Several versions of one package** | M | Same rules as `dotnet-package-skills`: versions shipping different skill names install together; the same skill name from two versions is an error; ownership is recorded per version. No side-by-side copies of one skill (the Agent Skills spec has no versions, and agents load skills by name). |
| A7 | **Compatibility check against `dotnet-package-skills`** | S | A test project referencing our sample package; their tool and ours install the same skills. |

### Block B: hardening and quality

| # | Item | Size | Done when |
|---|---|---|---|
| B1 | **Safe concurrent runs** | S | A lock per scope so two runs can't modify the same skills folder or lock file at once. |
| B2 | **Filesystem safety** | M | Never write through symlinks/junctions we don't own; reject names Windows misresolves (trailing dots or spaces, reserved device names); strip terminal escape sequences from skill metadata before printing. *Stricter than 1.x: may reject setups that work today.* |
| B3 | **Lock files identical on every OS** | S | LF line endings, no BOM, stable order; a committed `skills-lock.json` doesn't change between Windows and Linux. Verify current behavior first. |
| B4 | **Installs that fully succeed or change nothing** | M | Stage the new copy, swap it in, roll back on failure. |
| B5 | **`doctor`** | M | Finds broken symlinks, lock/disk drift, skills agents won't load (name/folder mismatch, bad frontmatter), duplicate names across scopes, missing agents, feed/registry problems. `--fix` repairs what's safe. |
| B6 | **Interactive picker** | M | Descriptions, paging, select-all/clear, `NO_COLOR`, resize-safe. |
| B7 | **Test depth** | M | Cover Windows, symlink, concurrency and failure paths; `dotnet-package-skills` has ~500 tests as a benchmark. |

### Block C: trust, authors, agents

| # | Item | Size | Done when |
|---|---|---|---|
| C1 | **Review before install** | M | `inspect <source>` and a review step in `add`/`sync`: files, scripts, the tools a skill allows (`allowed-tools`), anything unusual. `--review` gate for CI. |
| C2 | **NuGet signature verification** | M | Show signer; `--require-signed` refuses unsigned or untrusted packages. |
| C3 | **`validate`** | S | Lints a skill against the spec (name matches folder, allowed characters, description, size limits, frontmatter). Usable in an author's CI. |
| C4 | **`pack`** | S | Generates the csproj `ItemGroup` or `package.json` `files` entry for the `skills/` layout. |
| C5 | **Agents as data** | M | Built-in agents move to a data file; users add agents in `~/.agents/` without a release; expand toward upstream's coverage. |
| C6 | **`info <skill>`** | S | Source, version, feed, agents, files, alias for one installed skill. |
| C7 | **`feed add --map <pattern>`** | S | Write package source mapping from the CLI, with a clear warning that enabling mapping applies to every package. |

### Block D: team workflow and ecosystem

| # | Item | Size | Done when |
|---|---|---|---|
| D1 | **`skills.json` manifest with version ranges** | L | Declares what the team wants (separate from `skills-lock.json`, which records what was resolved). `add` writes it; `restore` and `update` respect its ranges; `--version-lock` builds on it. *Breaking: changes the add/restore workflow.* |
| D2 | **GitHub Action** | M | Runs `outdated --json` and opens update PRs; `restore --frozen` as a CI check. |
| D3 | **Speed** | M | Parallel source fetches; reuse the NuGet packages folder as a download cache. |
| D4 | **Docs** | S | Migration guide (1.x to 2.0, and from `dotnet-package-skills`), updated comparison pages. |

## Breaking changes planned for 2.0

1. Package skills install under their folder name (A5).
2. Stricter filesystem rules (B2).
3. `skills.json` manifest workflow (D1).

Each gets a migration note in the CHANGELOG and the migration guide.

## Decisions

| Question | Decision |
|---|---|
| Major version | 2.0 (breaking changes above). 1.1 ships first. |
| .NET 8 | Kept in 2.0. |
| How `sync` reads the project | `obj/project.assets.json`, falling back to `dotnet list package`. |
| Direct or transitive dependencies | Direct by default, `--transitive` to opt in. |
| Install name for package skills | Folder name, matching `dotnet-package-skills`, with a warning on mismatch. |
| Side-by-side versions of one skill | Not supported (no versions in the spec; agents load by name). |
| Previews | Open. |

## Deferred

- Native AOT, Homebrew, winget: not worth it while users are .NET developers.
- A hosted skills registry: NuGet and npm feeds already are the registry.

## Suggested build order

1. A1 `sync` and A5 install names, then A2 stale and A3 `--dry-run` (preview 1 candidate).
2. A4 coexistence, A6 versions, A7 compatibility check.
3. Block B (preview 2 candidate).
4. Block C (preview 3 candidate).
5. Block D, docs, release.
